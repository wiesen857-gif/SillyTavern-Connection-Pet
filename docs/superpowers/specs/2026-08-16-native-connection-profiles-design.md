# 酒馆原生连接配置读取与隔离应用设计

日期：2026-08-16

## 目标

连接桌宠自动读取 SillyTavern 已保存的连接配置，并允许用户在拓展设置面板或桌宠面板中一键应用。API 配置与提示词预设保持完全独立：应用 API 配置不得切换预设，也不得改变预设条目状态。

适配范围固定为 SillyTavern 1.16.0 的 `Chat Completion -> Custom`（OpenAI-compatible）。OpenRouter、DeepSeek 等独立供应商入口不在适配范围内；它们只有通过 Custom 兼容地址保存时才可能出现为可用配置。

## 已确认的宿主行为

SillyTavern 将原生连接配置保存在：

```text
extension_settings.connectionManager.profiles
```

Chat Completion 配置的 `mode` 为 `cc`，Custom 入口的 `api` 为 `custom`。原生连接配置还可能包含 `preset`、`proxy`、`reasoning-template`、`prompt-post-processing`、`regex-preset` 等字段。

SillyTavern 的原生连接配置应用流程会执行 `preset`。因此，本拓展不得调用原生 `/profile` 命令或复用原生的整套 `applyConnectionProfile` 行为。

## 配置来源与筛选

面板合并展示两类配置：

1. **酒馆现有配置**：从 `extension_settings.connectionManager.profiles` 动态读取，只保留同时满足以下条件的记录：
   - `mode === 'cc'`
   - `api === 'custom'`
   - 存在非空的 `api-url`
   - 存在非空的 `model`
2. **桌宠独立配置**：继续使用拓展自己的 `extensionSettings.connectionPet.profiles` 存储。

原生配置是只读数据，不复制进拓展设置，也不修改其内容。每次打开或刷新配置列表时重新读取，以反映用户在 SillyTavern 中的增删改。

下拉框用两个分组显示“酒馆现有配置”和“桌宠独立配置”。当某一组为空时不显示空分组。配置选项使用带来源前缀的内部值，避免两个来源的 ID 冲突。

## 隔离应用规则

无论从设置面板点击“立即应用”，还是从桌宠面板点击“一键应用”，最终都调用本拓展现有的 Custom 应用函数，只传入以下映射字段：

| 原生字段 | 拓展字段 | 用途 |
| --- | --- | --- |
| `api-url` | `apiUrl` | Custom API 地址 |
| `model` | `model` | 模型 ID |
| `secret-id` | `secretId` | 酒馆 Secrets 中的密钥记录 |
| `name` | `name` | 仅供界面显示 |

必须忽略原生配置的这些字段：

- `preset`
- `proxy`
- `stop-strings`
- `start-reply-with`
- `reasoning-template`
- `prompt-post-processing`
- `regex-preset`
- 所有未列入允许映射表的其他字段

应用顺序保持为：设置 Custom URL（暂不连接）→ 切换对应 Secret → 选择 Custom API → 设置模型 → 使用 URL 发起连接。读取配置和选择配置都不改变宿主状态，只有用户点击应用按钮后才执行上述操作。

## 设置面板交互

“API 配置”页的配置下拉框同时显示两个来源：

- 选中酒馆现有配置时，名称、URL、模型和 Secret 以只读方式展示；保存、删除不可用；提供“复制为桌宠配置”，复制后得到可编辑的独立配置。
- 选中桌宠独立配置时，维持现有的新建、保存、复制、删除和立即应用能力。
- 点击“立即应用”时使用当前选中的任一来源配置，并在状态区明确显示应用成功或失败。

拓展不在后台自动应用配置，也不自动把酒馆当前选中的原生配置设为桌宠的活动配置。

## 桌宠面板交互

桌宠的“API 配置”页使用与设置面板相同的合并配置列表。摘要显示配置来源、模型和 API 地址。点击“一键应用”后，只应用允许映射表中的 API 字段。

应用成功后，桌宠在本地记住所选项的来源与 ID，以便下次打开时恢复选择。若原生配置已被删除，选择回退到空状态并提示重新选择，不保留一份可能已过期的隐式副本。

窄屏下，设置页的操作按钮使用两列横向布局；“立即应用”和桌宠的“一键应用”使用整行按钮，避免按钮文字逐字竖排。

## 预设条目行为

“预设条目”页与 API 配置页保持独立：

1. 用户先选择一个提示词预设。
2. 设置面板读取该预设的所有条目，用户将其中部分条目加入“待开启条目”。
3. 桌宠只显示已加入待开启列表的条目。
4. 用户点击某个条目的开关时，拓展先切换到该预设，再只修改该条目的启用状态。

应用 API 配置不会触发以上流程；切换或修改预设条目也不会应用任何 API 配置。

## 模块边界

- `host-adapter.js`：读取并规范化酒馆原生连接配置；继续负责执行受限的 Custom API 应用命令。
- 新增纯数据模块：筛选、映射、合并两类配置，并生成稳定的来源标识。该模块不访问 DOM，便于单元测试。
- `settings-panel.js`：渲染分组列表、控制只读/可编辑状态和复制操作。
- `pet-widget.js`：渲染合并列表并调用同一应用入口。
- `settings.js`：保存桌宠当前选择时记录来源与 ID；兼容现有 `activeProfileId` 数据并迁移为桌宠独立配置来源。

## 错误处理

- `connectionManager.profiles` 缺失或不是数组时，按“没有酒馆现有配置”处理，桌宠独立配置仍可使用。
- 字段缺失、不属于 `cc/custom` 或 URL/模型为空的原生配置不展示。
- 原生配置引用的 Secret 不存在时仍展示配置，但应用时报出“密钥已不存在或不可用”，不静默改用其他密钥。
- 任一斜杠命令失败时停止后续步骤，状态区显示错误，不能报告成功。
- 原生配置在选择后被删除时，应用前重新解析；找不到则拒绝应用并要求重新选择。

## 验证与验收

单元测试至少覆盖：

- 只筛选 `mode=cc` 且 `api=custom` 的有效原生配置。
- 映射结果只包含名称、URL、模型、Secret ID，不包含 `preset` 等字段。
- 原生配置和桌宠配置 ID 相同时仍能正确区分。
- 旧版 `activeProfileId` 能迁移为桌宠独立配置选择。
- 被删除的原生配置不能继续应用。
- 缺失连接管理器数据时独立配置仍可使用。
- 应用成功和命令失败路径。
- 切换 API 配置不会调用任何预设操作；切换预设条目不会调用 API 应用操作。

浏览器冒烟测试至少确认：

- 设置面板显示两个来源分组和正确的编辑状态。
- 桌宠面板能选择并应用酒馆现有配置。
- 窄屏按钮不再竖排。
- 页面加载与交互过程中控制台无未处理错误。

验收标准：选择一个含有 `preset` 字段的酒馆原生 Custom 配置并点击应用后，API 地址、模型和 Secret 随之变化，但当前提示词预设及其所有条目启用状态保持不变。
